# ADR-010: 写真未登録メンバーのプレースホルダーを TRIAX ロゴ透かし画像にする

## ステータス

承認済み（2026-09-05）

## コンテキスト

ADR-009 で メンバーデータの正を hub に移した結果、切替時点で写真が登録されているメンバーは 5 名程度で、
MEMBERS セクションの大半が写真未登録の状態になった（Issue #22）。

- 写真未登録時と画像の読み込み失敗（`onerror`）時は、`docs/index.js` に埋め込んだインライン SVG
  （`#e5e7eb` 地に `#9ca3af` の "No Image" テキスト）が表示されていた
- 汎用的な「No Image」表記はブランドの世界観と噛み合わず、写真が揃っていないことをかえって目立たせていた
- 表示箇所は 3 つ（MEMBERS カード表面・選手詳細モーダルのカルーセル・トップのピックアップ円形表示）で、
  正方形 `object-cover` と円形クロップの両方で成立する素材が必要
- 素材はリポジトリで git 管理し、ビルド生成物（`docs/assets/members/`）とは分ける必要がある

## 決定

### 1. 採用デザイン: `gradient-center-60-op18`

| 項目             | 値                                                                                           |
| ---------------- | -------------------------------------------------------------------------------------------- |
| キャンバス       | 800×800（`build-members.ts` の `PHOTO_MAX_EDGE` と同じ）                                     |
| 地色             | 縦グラデーション `#f3f4f6`（上）→ `#d1d5db`（下）                                            |
| ロゴ             | `docs/assets/triax-logo.png` をえんじ色 `#853734`（`--primary-color`）で再着色、不透明度 18% |
| ロゴサイズ・配置 | 高さをキャンバスの 60% にして中央配置（円形クロップでも見切れない）                          |
| 付加要素         | なし（文字なし）                                                                             |
| 出力             | JPEG 品質 85・8-bit・`-strip`、約 13KB                                                       |

### 2. 配置場所と生成方法

- 素材は `docs/assets/member-placeholder.jpg` に置き、**git 管理する**。`docs/assets/members/` はデプロイごとに
  作り直される生成物なので、その外に置く
- 生成は `scripts/generate-member-placeholder.sh` に一本化する。採用パラメータはスクリプト先頭の `ADOPTED_*`
  定数にまとめ、`--production` で本番ファイルだけを書き出す

  ```bash
  ./scripts/generate-member-placeholder.sh --production
  ```

- 引数なしで実行すると比較に使った全サンプル（第 1・第 2 ラウンド）を `knowledge/plans/member-placeholder-samples/`
  （gitignore 済み）に再生成できる。デザイン履歴の再現用

### 3. サイトでの使い方（`docs/index.js`）

- 定数 `PLACEHOLDER_PHOTO = 'assets/member-placeholder.jpg'` が唯一の参照点。旧 `NO_IMAGE_PLACEHOLDER`
  （インライン SVG）は削除
- 使用箇所は 3 つ
  1. `createMemberCard`: 写真が 1 枚もないメンバーのカード表面
  2. `showMemberDetail`: 写真が 1 枚もないメンバーのモーダルカルーセル（1 枚だけ表示）
  3. `displayRandomMemberPickup`: ピックアップされたメンバーに写真がないとき、`src` に直接プレースホルダーを使う
     （これまでは写真がないと何も描画せず終了していた。`onerror` の往復に頼らない）
- 画像の読み込み失敗時は `showNoImage(img)` が同じ画像へ差し替える（3 箇所とも `onerror` 経由のフォールバックを維持）。
  差し替え前に `onerror` を外すので、プレースホルダー自体が読めなくてもループしない
- プレースホルダー表示時の `alt` は `{名前}（写真準備中）` にする

## 理由

- **写真が主役のまま**: 第 2 ラウンドで実際の写真と混ぜた MEMBERS グリッドを作ったところ、明るいグラデーション地は
  背景に退いて写真が視線の焦点として残る。未登録者が大半を占める当面の状態でも、一覧が「プレースホルダーだらけ」に見えにくい
- **円形でも正方形でも成立**: ロゴを中央 60% に収めることで、ピックアップの円形クロップとカードの `object-cover` の
  両方でロゴが見切れない
- **18% は視認性と控えめさの均衡点**: 12% ではカードサイズでロゴが薄すぎて判別しにくく、18% なら透かしとして読める
- **1 素材で 3 箇所**: 場所ごとに素材を分けない。運用も参照も単純になる

## 代替案（比較ラウンドで実際に評価したもの）

### 第 1 ラウンド: 10 案

地色（ライトグレー / オフホワイト / ダーク / ブラック / えんじ / グラデーション）× 配置（中央 / 右下はみ出し）
× キャプション有無を組み合わせて生成し、カード・円形・モーダルの 3 形状に嵌めた比較 HTML で確認した。

- **右下はみ出し配置（`light-corner-130` / `dark-corner-130`）**
  - 利点: 動きがあり、ブランド感が出る
  - 不採用の理由: ピックアップの円形クロップでロゴが大きく切れ、何の図形か分からなくなる
- **キャプション付き（`light-center-60-caption`: "PHOTO COMING SOON"）**
  - 利点: 状態が言葉で伝わる
  - 不採用の理由: 「No Image」を置き換える動機と矛盾する余計な文字。`alt` で伝えれば足りる。フォント環境への依存も増える
- **ダーク / ブラック / オフホワイト地・ロゴ 40% 版**（`dark-center-60` / `black-center-60` / `offwhite-center-60` / `light-center-40`）
  - 不採用の理由: 比較の結果、最終候補 2 案に残らなかった
- 第 1 ラウンドの最終候補は `maroon-center-60`（地 `#853734`・白ロゴ 15%）と `gradient-center-60`（採用案の 12% 版）

### 第 2 ラウンド: 最終候補 2 案の派生 7 案

えんじ地の不透明度違い（10 / 15 / 20 / 25%）とやや暗いえんじ地、グラデーション地の不透明度 18%・放射グラデーション・
ロゴ 70% を生成し、実写真と混ぜた MEMBERS グリッドのモックで比較した。

- **`maroon-center-60` 系（えんじ地・白ロゴ）**
  - 利点: ブランドカラーそのもので統一感が強い。ヒーロー直下のピックアップ円では単体で最も映える
  - 欠点: グリッドに並べると濃色タイルが写真より強く、プレースホルダーが「特集タイル」に見えて写真が脇役になる
  - 不採用の理由: 未登録者が多い期間ほど一覧の主役が入れ替わってしまう。ピックアップ用にだけえんじ版を分ける案も
    あったが、1 素材で 3 箇所を賄う単純さを優先した
- **`gradient-center-60`（12%）/ `gradient-radial-center-60` / `gradient-center-70`**
  - 不採用の理由: 12% はカードサイズで薄すぎてロゴが判別しにくい。放射グラデーションとロゴ 70% は、縦グラデーション
    60% の不透明度を 18% に上げた案（採用）と比べて選ぶ決め手がなかった

### 実装面の代替案

- **SVG / PNG / WebP で置く**: 透過は不要で、JPEG 品質 85 で 13KB に収まる。写真と同じ形式に揃えた
- **ビルド時に生成する**: 毎回同じ画像を作るだけで、ImageMagick の依存を CI の必須経路に増やすだけ。git 管理した方が単純

## 結果

### 良い影響

- 写真未登録メンバーのカード・モーダル・ピックアップがブランド調で統一され、「No Image」の文字が消える
- ピックアップに写真未登録メンバーが選ばれても空欄にならない
- 素材の変更はスクリプトの `ADOPTED_*` を直して `--production` を実行するだけ

### 悪い影響

- 画像リクエストが 1 本増える（約 13KB、キャッシュされる）

### リスク

- `docs/assets/member-placeholder.jpg` を誤って削除すると 3 箇所とも壊れる。`showNoImage` はループしないが表示は空になる。
  `--production` で再生成できる

## 実装への影響

- 変更ファイル: `docs/assets/member-placeholder.jpg`（新規）、`docs/index.js`、`scripts/generate-member-placeholder.sh`
- 運用手順: `knowledge/04-operations/hub-members-sync.md` の「写真未登録メンバーの表示」
